# educationagent 服务器部署

目标环境为 Ubuntu 24.04、2 vCPU、4 GiB 内存。Java 21 运行现有后端，项目专用 Node 运行 `course-engine/dist/worker.js`；Caddy 提供 `https://smartchildcareagent.cn` 和公共可信证书。网站免登录，打开即可使用课堂；当前为公开单用户课堂，访问者共用课程和学习记录。MySQL、Redis、Java 只监听本机回环地址。生产配置使用 `server` profile，不加载开发 profile。

## 目录与配置

```text
/opt/educationagent/
  runtime/node -> node-v24.19.0-linux-<架构>  # 项目专用，不改全局 PATH
  releases/<发布号>/                       # 只读代码、构建产物、Linux 依赖
  current -> releases/<发布号>
  shared/data/                            # 课堂语音、微信配对、记忆索引等
  shared/logs/                            # 业务埋点；Java 输出另进 journal
/etc/educationagent/runtime.env            # root:root 0600，模型与数据库秘密
/etc/caddy/educationagent.env              # 仅域名
```

发布目录的 `data`、`logs` 是指向 `shared` 的链接。不要把本机数据、模型密钥、`config/local-secrets.properties`、Windows `node_modules`、聊天记录或数据库文件打进发布包。代码目录由 root 管理，Java 以 `educationagent` Unix 用户运行；`shared` 才是该用户的可写持久目录。

`deploy/linux/server.env.example` 列出了生产实际读取的变量。请通过安全通道写入服务器的 `runtime.env`，不要提交真实文件。`AI_CHAT_*` 只配置文本模型；语音、图像和 embedding 的凭据相互独立，不能把文本模型可用视作这些服务已经可用。

## 首次部署顺序

1. 本地先完成现有构建和测试：workspace 生成器、`desktop-app` 网页与 Java JAR。公网网页构建时设置 `VITE_PUBLIC_CLASSROOM=true`，显示学习、复习和成长知识入口；未设置时本机版保留原有工具导航。将 Java 产物命名为发布目录中的 `app.jar`。发布包还需含根 `package.json`、`package-lock.json`、`course-engine`、`vendor/educationagent` 及其已构建 `dist`、`desktop-app/dist`、`deploy/linux`。保留共享包的依赖声明。
2. 核实服务器身份、已有监听与服务归属；本脚本面向已确认的独立服务器。核实 Node 指定版本已存在于 `nodejs.org` 官方下载目录后，以 root 执行 `bash deploy/linux/bootstrap-host.sh 24.19.0`。下载按官方 `SHASUMS256.txt` 校验。脚本安装 Ubuntu 原生 MySQL、Redis、Caddy、Java JRE，不更改 SSH、全局防火墙、代理或无关服务。
3. 将发布包放进 `/opt/educationagent/releases/<发布号>`，解压后保留 Linux 可读取权限。准备 `/etc/educationagent/runtime.env`，设为 root 所有、权限 `0600`；数据库用户名固定 `educationagent`。网站不配置访问凭据，Caddy 环境文件仅保存域名。
4. 从发布目录执行 `bash deploy/linux/configure-local-services.sh`。它创建专用数据库与局部账户、Redis 缓存认证、Caddy 环境文件和 systemd 单元；MySQL/Redis 重启仅用于采用本项目本机配置。凭据经本机标准输入或保护文件传递，不出现在命令行参数和输出中。不得开启 shell `set -x`。
5. 配置域名 A 记录到已核实的服务器公网 IP；只有有对应 IPv6 服务时才保留 AAAA。云防火墙需允许 TCP 80/443，供 ACME 与 HTTPS 使用；数据库、Redis 和 8888 不开放公网。已有 DNS 记录先检查再修改。
6. 执行 `bash deploy/linux/install-release.sh <发布号>`。它在 Linux 生成 workspace 依赖链接，运行生成器 `--check`，切换 `current`，启动 Java，等待本机课堂健康检查通过后加载 Caddy。健康失败时恢复上一版代码链接；没有上一版则停止应用，并保留失败发布目录供排查。
7. 执行 `bash deploy/linux/verify.sh`，再用浏览器直接访问域名，确认页面无登录提示，验证课程列表、创建课程、生成大纲、页面生成、提问、进度保存和重新载入。首页应返回 200，未公开的工具与管理 API 应返回 404。真实模型生成必须单独测试。本机健康通过不能代替公网 HTTPS 和完整课堂验收。

配置脚本仅针对本项目专用 MySQL 数据库授权；不修改 MySQL root 密码。Redis 按可丢缓存配置，限制 128 MiB，不持久化；长期课程保存在 MySQL。部署脚本从同版 `app.jar` 提取 `schema.sql`，排除其中的演示班级和学生映射 INSERT 后导入结构；服务器 profile 关闭 Spring 自动执行原始脚本，Java 启动仍运行既有增量迁移。遇到新增加的数据写入语句，部署脚本会要求先审查，不盲目导入。升级若涉及数据库结构，先审查变更并备份；代码链接回退不会回退数据库结构或学习数据。

## 生产开关与能力边界

- `application-server.properties` 关闭演示教师自动创建、演示数据填充和遗留固定 token；微信默认不自动扫码。教师管理接口保留在 Java 本机，公网入口不提供管理界面或演示教师。
- MCP 保持懒加载且默认关闭未配置的远程集成。已有模块代码保留，后续配置相应服务后再显式启用。
- 首次部署默认关闭 Chroma 与记忆向量注入，embedding 提供方指向本机 Ollama 地址，避免无凭据时向外部 embedding 供应商探测。现有 embedding Bean 仍会做本机启动探测；若未安装 Ollama，日志会显示该能力未就绪，核心课堂文本生成不依赖它。
- Chroma 如需启用，应另建独立 Python 3.12 venv 和 systemd 服务，监听 `127.0.0.1:8001`；检查实际 embedding 模型、维度、索引来源和内存后，才调整 `MEMORY_CHROMA_ENABLED` 与 `MEMORY_EMBEDDING_PROVIDER`。不要声称仅启动核心课堂就已验证全部知识库。
- 腾讯语音和其他供应商凭据未配置时，网页文字学习仍可使用；录音转写、云 TTS、微信登录及微信原生语音需分别验收。域名可信 HTTPS 为浏览器录音提供安全上下文，实际权限仍由设备授予。
- 公网只反向代理 `/api/classroom` 及其子路径、`/api/desktop/quiz/*`、`/api/desktop/psychology/*`、`/api/desktop/lifesafety/*`、`/api/desktop/sexedu/*` 和 `/actuator/health`；其余 `/api`、`/chat`、`/actuator` 下接口返回 404。本机 Java 原功能继续保留，文件、系统工具和运维管理接口不通过网站暴露。
- 当前公开站共用课程和学习记录，不区分访问者。网站不新增注册、登录页或验证码。微信扫码确认和设备麦克风授权仍由用户在实际设备上完成。

## 运维与回退

```bash
systemctl status educationagent caddy mysql redis-server --no-pager
journalctl -u educationagent -n 100 --no-pager
journalctl -u caddy -n 60 --no-pager
bash /opt/educationagent/current/deploy/linux/verify.sh
```

日志可能含模型正文和使用记录，不公开转发完整日志。不要输出 `runtime.env`，不要用 `systemctl show ... Environment` 排障。Caddy 续证由其服务和持久存储管理；保持 80/443 与域名解析可达。

更新时使用新的发布号，重跑构建与验证后再安装；不覆盖旧发布目录或 `shared`。回退前先确认目标发布目录真实存在且在 `/opt/educationagent/releases` 内，再以原子链接切换 `current` 并重启本项目服务。任何旧版本清理和数据恢复都需单独决定，部署脚本不会删除历史发布或学习数据。

Java 堆上限为 900 MiB，Node 子进程堆上限为 384 MiB，MySQL buffer pool 为 384 MiB，Redis 上限 128 MiB。systemd 对本项目进程组另设 1.8 GiB 上限，为系统与数据库留出空间；生成并发和向量库加入后应按实际测量重新评估，不能将 JVM 堆上限当作整个服务的峰值内存。

## 可选：独立 Chroma 向量服务

`deploy/linux/install-chroma.sh` 仅在已准备好项目目录与 Python 3.12 venv 支持的服务器上手动执行，不随核心课堂安装自动运行。它使用 `/opt/educationagent/runtime/chroma` 专用 venv，固定安装 `chromadb==1.0.20`，不改变系统 Python，不覆盖其他 Chroma 安装或监听者。检测到同名但内容不同的服务、未知 venv、非本项目的数据目录或其他进程占用 8001，会停止并保留现状。

该版本 [官方 PyPI 发布包](https://pypi.org/project/chromadb/1.0.20/) 的 Python CLI 转调 Rust CLI；同版 [官方 run 实现](https://github.com/chroma-core/chroma/blob/1.0.20/rust/cli/src/commands/run.rs) 明确支持 `--host`、`--port`、`--path`。本项目单元使用以下命令，持久数据归 `educationagent` 用户所有：

```bash
/opt/educationagent/runtime/chroma/bin/chroma run \
  --host 127.0.0.1 --port 8001 \
  --path /opt/educationagent/shared/data/chroma
```

安装与只读检查：

```bash
bash /opt/educationagent/current/deploy/linux/install-chroma.sh
systemctl status educationagent-chroma --no-pager
journalctl -u educationagent-chroma -n 60 --no-pager
curl --fail --silent http://127.0.0.1:8001/api/v2/heartbeat
ss -lntp '( sport = :8001 )'
```

脚本在服务就绪后只读取并校验 v2 heartbeat；该路由由同版 [官方 server 实现](https://github.com/chroma-core/chroma/blob/1.0.20/rust/frontend/src/server.rs) 提供。此检查不创建集合、不写入测试数据，也不证明 embedding 或检索链路已经可用。

服务设置 `ANONYMIZED_TELEMETRY=False`，单机默认配置未设置 OpenTelemetry collector；systemd 同时以 `IPAddressDeny=any`、`IPAddressAllow=localhost` 将网络限制为本机。执行后需检查 journal 中没有“BPF/IP firewall 不受支持”等提示，并确认实际只有 `127.0.0.1:8001` 监听。该服务仅接收 Java 已计算的 1024 维 embeddings，不调用 Python 默认嵌入函数、不下载 ONNX 或 Hugging Face 模型；不开放到 Caddy 或公网。不要通过 Python 默认客户端的 `query_texts` 或只传文档的 `add` 来代替 Java 的向量协议验证。

Chroma 进程组 `MemoryHigh=550M`、`MemoryMax=650M`；超限可能被系统终止，容量与索引增长需根据真实数据观察。Java 的向量开关和 embedding 模型、地址、密钥仍由受保护配置单独管理，安装脚本不会读写 `runtime.env`。确认 Chroma、embedding 真实维度和小样本检索均通过后，再启用 `MEMORY_CHROMA_ENABLED` / `MEMORY_INTEGRATION_ENABLED` 并重启本项目 Java 服务。若启用后需要保证开机顺序，可为 `educationagent.service` 添加本项目专属 drop-in 的 `Wants=educationagent-chroma.service` 和 `After=educationagent-chroma.service`，再重新加载 systemd；不修改其他服务依赖。
