# childcare-smart机制适配清单

来源根目录：`D:/Desktop/childcare-smart源代码/childcare-smart`。本轮迁移四类设计机制到现有Java/Node架构；不是整体复制Next.js托育产品，也未找到可直接搬用的Bilibili推荐器。源文件函数、哈希和本地代码行由[代码索引](research-20261016/代码位置索引.csv)与[映射清单](research-20261016/实现映射.json)绑定。代码索引中的upstream路径相对上述参考项目，主项目code/tests路径相对本仓库。

## 1. 共用请求截止时间

- 来源：`lib/providers/vivo/vivo-client.ts` 的 `vivoFetchWithDeadline`、`vivoJsonRequest`、`wrapVivoTransportError`。
- 原机制：超时信号与调用方取消信号组合，HTTP头返回后继续约束正文读取，并区分取消、超时、鉴权、限流等错误。
- 本轮实现：`ClassroomAiGateway.execute/perform` 的一个deadline覆盖请求、正文、解析、validator和可选修订；取消传播到等待任务与HTTP请求。
- 适配差异：Java虚拟线程和JDK HttpClient替代TypeScript fetch；接收时限制512KiB响应体；错误证据不保留响应正文、密钥、完整地址或异常原文。
- 重试规则：只有收到完整但违反输出合约的响应时允许最多一次结构修订。401/403、429、超时、连接中断、缺正文和截断生成均不自动再次请求。
- 对应测试：`slowBodySharesDeadlineWithHeadersAndIsNotRetried`、`parsingValidatorAndRepairShareOriginalBudget`、`authenticationRateLimitAndServerErrorsNeverRetry`。

## 2. 有界生成—评价—修订

- 来源：`backend/app/services/evaluator_optimizer.py` 的 `EvaluatorOptimizer.run`、`_should_replace_best`；`backend/app/agents/generator_evaluator.py`是服务调用入口。
- 原机制：最大候选次数、保留最好候选、相同输出/相同失败停止，以及不可重试状态停止。
- 本轮实现：`ClassroomTeachingReview.review` 对结构有效的单页执行规则核对和语义核对；最多提出一次文本补丁，并再次核对后决定是否采用。
- 适配差异：不迁移原来的托育发送评分阈值8分；使用pass/needs_revision/unknown及grade/goals/sources/interaction维度。只改允许的标题、讲述、讨论主题或课件文本；不允许改ID、答案、HTML/JS、动作控制或任意JSON路径。
- 一次修订不通过时返回原内容及明确状态，不覆盖有效内容。语义复核至多两次模型调用，调用 `structuredOnce` 避免结构修订再叠加形成四次调用。
- 互动HTML只进行静态内容检查，`runtimeVerified=false`。真正的参数和结果联动仍需浏览器验收。
- 对应测试：`exactlyOneTextRevisionIsAdoptedOnlyAfterRecheck`、`failedRecheckRestoresOriginalCandidateAndDoesNotLoop`、`disallowsChangingHtmlIdentifiersOrAnswers`。

## 3. 模型来源与实际调用证据

- 来源：`lib/ai/provider-trace.ts` 的 `buildAiProviderTrace`、`buildAiProviderTraceHeader`、`normalizeAiCapabilityMode`。
- 原机制：区分configured/live/fallback/mock，携带provider/model/requestId等来源信息。
- 本轮实现：`ClassroomAiGateway.Trace` 保存实际响应model、requestId、HTTP状态、调用次数、耗时、合约验证状态和上游提供的tokenUsage；模型未返回的字段为null。
- 适配差异：证据保留在服务端，不把提示词或内部trace放进学生公开响应；配置存在只代表configured，不宣称在线调用成功。为新资源语义缓存额外绑定提供方、模型、维度与文本规范版本。
- 对应测试：`recordsActualProviderModelIdUsageAndDisabledThinking`、`missingActualMetadataStaysNullRatherThanInvented`、`providerMetadataCannotEchoCredentialIntoEvidence`。

## 4. 结构化反馈与任务关联

- 来源：`lib/feedback/normalize.ts` 的 `normalizeParentStructuredFeedback`、`dedupeFeedbacks`，`lib/feedback/consumption.ts` 的 `collectStructuredFeedbackCandidates`、`selectStructuredFeedback`；`writeback.ts`提供幂等写回思路。
- 原机制：归一化、去重、执行/反应/改善状态分开，优先匹配任务或咨询。
- 本轮实现：学习尝试按课程、章节、内容指纹及requestId保存；首次表述不原位覆盖；历史查询和后续提示/自检绑定同一尝试。推荐opened/helpful/not_helpful/too_long/tried是不同事件。
- 明确改动：原 `selectStructuredFeedback` 最后的 `return candidates[0]` 会在任务不匹配时回退到最近反馈。本轮取消此兜底，不跨课程、章节或资料版本取反馈。
- 对应测试：`duplicateFirstSubmissionCannotRewriteOriginalText`、`differentCourseAndKindNeverLeakIntoHistory`、`historyIsSceneBoundAndReturnsAtMostTenNewestAttempts`、`realSubmissionScoresOnceAndCannotMutateCourseOrInitialUnderstanding`。
