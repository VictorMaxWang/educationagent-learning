# 面向乡村普惠教育多学科场景的多层安全管控链路

> **口径说明（请先读这一段，答辩时也照这个讲）**
> 本文每一条声明都对应到具体代码位置；**尚未实现的明确标注「规划中」并给出设计**。
> 之所以这样写：技术评委最容易问"这一层能不能演示一下"。把"没做"说成"做了"，
> 一旦被追问，**前面讲对的那些也会一起失去可信度**；而把"已做 / 规划中"分清，
> 反而显得工程判断成熟——这也是本项目文档一贯的做法（见技术债清单）。

## 核心思想

安全管控**层层前移**：从用户输入 → 意图路由 → RAG 检索 → 内容生成，逐层拦截风险，
避免敏感知识库被误召回、违规内容流出。本项目自研「规则 → TF-IDF → LLM」三层混合前置路由，
安全链路与之**同层并联**而非事后补丁。

## L1 规则层安全拦截（**已实现**）

**机制**：安全规则是 `RuleBasedRouter` **L1 的第一条规则**，命中高危表述即给出
`BLOCKED` 判决，**终止请求并返回固定引导话术**——不拼提示词、不调大模型、不发起向量检索。

**为什么"放进 L1"就等于"终止链路"**
`HybridRouter` 的漏斗语义是"任何一层给出非 FALLBACK 的结论即采纳"，而安全规则排在 L1 首位，
因此 `BLOCKED` 会**短路 L2 与 L3**（含 L3 的那次 LLM 调用）——不需要调用方再补一层判断。

**实测证据（2026-10-15 一次真实运行）**

```
🛡 L1 安全规则已装载：自伤自杀 45 词 + 违规内容 41 词；健康白名单 22 词
ROUTE | layer=L1 | decision=BLOCKED | intent=null | conf=1.000 | cost=6ms
🚨 安全闸门命中 SELF_HARM | keyword=不想活
📊 危机信号计数 +1 → 班级=class_demo_1 日期=2026-10-15
🔵 推送正文片段 #1 | 距流开始 51ms
```

同一轮里**没有** `FSM:LLM_CALL`、**没有** `自定义 DeepSeek 流式已启用`，
且 51ms 就产出正文（正常问答是数秒）——这就是"零大模型调用"的现场证据。

> 注：日志里该判决的 `tools=1` 不是"空集失效"，而是漏斗层按配置并入了「通用工具」
> （`router.tool-filtering.general-tools`，默认 `[searchWeb]`）。L1 本身给的是空集；
> 且短路发生在组装提示词之前，这个工具集不会被使用。

**接入点（两段式：L1 主拦 + 兜底）**

| 路径 | 代码位置 | 说明 |
|---|---|---|
| 主路径 | `RuleBasedRouter.trySafety()`（L1 第一条规则） | 对话链路；命中即 BLOCKED，L2/L3 不执行 |
| 对话兜底 | `AgentExecutor.chat()` / `chatStream()` 的 `safetyShortCircuit()` | 路由被关闭/异常时仍然判定 |
| 知识库链路 | `BaseDocKnowledgeController.search()` | 这条链路**不经过路由**，必须单独守 |

**关键设计**

- **安全不挂在功能开关上**：`router.enabled=false` 或 `router.rule.enabled=false` 时 L1 整层不跑，
  而这一层恰是风险的唯一自动防线。所以 `AgentExecutor` 的兜底判定**每次都跑**——
  代价只是一次约 60 词的字符串包含判断（微秒级），换来的是"无论怎么配开关，风险消息都进不了模型"。
- **判定源只有一份**：`SafetyKeywordRules` 内部**复用**自伤词表组件，不另抄一份——
  两套风险词表一定会漂移，而漂移的后果是"某个入口漏检"。
- 图片/语音/文件在两端预处理后**已拼成同一个字符串**，所以藏在媒体描述里的信号同样命中。
- 判定**刻意不做否定消歧**（"我不想死"也会命中）：漏报的成本远大于误报。

**词表范围（三类，均已实现）**

| 类别 | 规模 | 处置 |
|---|---|---|
| 自伤 / 自杀风险 | 约 40 条（显式意念、方法性词汇、无望感、隐喻式告别） | 引导话术（12356 / 12355 / 告知成年人）+ **脱敏计数** |
| 索取色情资源 / 性交易 | 约 20 条（黄色视频、裸照、约炮、招嫖…） | 拒绝话术 + **不计入危机计数** |
| 违法实施方法 | 约 15 条 | 同上 |

**两处刻意的收词原则（这是这一层最难的地方）**

1. **不合并两类计数**。危机计数的口径是"自伤风险"，把色情/违法请求混进去会让教师端那个数字失去意义；
   所以违规内容只记日志、不进 `edu_crisis_daily`。
2. **只收"求方法"的动词短语，不收光杆名词**。
   `怎么盗号` 是实施请求，`我的号被盗了怎么办` 是被害人求助——后者必须能答。
   同理不收光杆 `杀人`/`盗窃`/`毒品`（法律与健康知识库的正常提问），
   也不收 `做爱`/`性行为`（性教育里必然出现的提问用词）。
   这条边界有回归测试（`SafetyKeywordRulesTest.distinguishesIntentFromVictimhood`）。

**"白名单"的实现方式（比常规做法更严）**

不是运行期"命中白名单就放行"——那样会留一个洞（"月经期间能看黄片吗"含健康词会被整体放行）。
本项目用的是 **构建期冲突校验**：`SafetyKeywordRules.assertNoConflict()` 检查黑名单词汇
是否与健康教育白名单（月经、遗精、避孕、生殖期、性骚扰…）语义重叠，
一旦有人把"性行为""避孕套"这类词加进黑名单，**启动即报错、测试即失败**。
与其在运行期事后放行，不如在构建期不让它进来。

## L2 模糊风险语义层（**已实现，阈值与模式均由实测决定**）

**机制**：与意图分类**共用同一个 TF-IDF 质心模型**，只是多了一个特殊的 `RISK` 类
（15 条风险语料，与 L1 的精确关键词**刻意不重叠**——L2 要抓的正是 L1 漏掉的那部分）。
命中即 `BLOCKED`，**不进入 RAG、不进 LLM**。

**它凭什么不冗余于 L1**（实测对照）：

| 措辞 | L1（精确关键词） | L2（模糊语义） |
|---|:--:|:--:|
| 「撑不下去了」「好想一了百了」 | ❌ 拦不到（词表没有） | ✅ 拦到 |
| 「自杀率上升的原因是什么」 | ⚠️ **误拦**（含"自杀"） | ✅ 不拦 |
| 「割腕的伤口怎么护理」 | ⚠️ **误拦**（含"割腕"） | ✅ 不拦 |

标注集上 **7 条知识型反例（自杀率/割腕护理/抑郁症表现/安乐死立法/死亡赔偿金/识别情绪危机…）
一条都没被 L2 误报**。两层是互补的，不是重复建设。

**阈值是扫出来的，不是拍的**（`RiskLayerEvalTest`，15 条正例 / 14 条反例）：

| 阈值 | 召回 | 误报 |
|---|---|---|
| 0.40 | 0.0% (0/15) | 0.0% |
| 0.35 | 26.7% (4/15) | 0.0% |
| 0.30 | 60.0% (9/15) | 0.0% |
| **0.25（当前默认）** | **86.7% (13/15)** | **7.1% (1/14)** |
| 0.20 | 93.3% (14/15) | 7.1% |
| 0.15 | 93.3% | 14.3% |

初版按"模糊层要更严"拍了 0.35，实测只抓到 1/4；**扫描后发现 0.35 过于保守**，
0.25 是拐点（再降只多 1 条召回、误报翻倍）。模式取 `enforce` 也是数据支撑的结论，
不是"模糊层一律不拦"——想更保守可改 `log`。

**如实记录的边界（两条）**

1. **有一组措辞靠字面分不开**：漏报的「想彻底休息一下」与误报的「我好想请假休息一天」
   字面几乎一样、语义一个该拦一个不该拦。这是 TF-IDF 这一类方法的固有边界，
   要么接受，要么在语料层面回避这类歧义措辞。
2. **误报率的口径**：上表是**人工标注集**上的数字，可复现、可作回归基线，
   **不等于真实流量误报率**。真实值要用 `router.tfidf.risk.mode=log` 跑一段时间，
   从 WARN 日志 + `logs/router-eval.jsonl` 统计。

**人工复核的口径（这里必须二选一）**

"转人工复核"需要看到原句才能复核，而本项目的隐私承诺是**不存提问内容**。两者不能同时成立。
本项目选择：**复核通道只记录「命中类型 + 班级 + 日期 + 计数」，不保留原句**——
教师端看到的是"本班本周有 N 条需关注的风险提问"，用于**线下关注**，而不是逐条阅读学生问了什么。
若日后要保留原句，必须在隐私政策里明确写"安全复核为隐私例外"并限定留存期。

## L3 命名空间隔离与按班过滤（**物理隔离 + 元数据过滤已实现；权限分级为下一步**）

**已实现（这一条可以按"已实现"讲，且能指代码）**

1. **学科级命名空间物理隔离**：每个学科 / 子库对应**独立向量集合**，物理上互不混装：

| 学科 | 集合 |
|---|---|
| 通识教育 | `tongshi_politics` / `tongshi_english` / `tongshi_math` |
| 心理学 | `psychology_general` |
| 生命安全与健康教育 | `lifesafety_life` / `lifesafety_support` |
| 青春期性教育 | `sexedu_puberty` / `sexedu_relationship` / `sexedu_protection` |
| 校本资源 | `school_school` |

检索只发生在目标集合内：**通识课的提问不会去碰专题库，反之亦然**——
这层隔离由领域配置（`DocKnowledgeConfig` → 集合前缀）保证，不是运行时判断。

2. **校本资源的按班隔离**（完整链路已打通）：
   - 教师上传时给文件登记 `classId`（侧车 `data/school-knowledge/.meta-map.json`，
     它是索引器的通用机制："文件 → 一组元数据"，语义由调用方定义）；
   - 索引时该 `classId` 被写进每个 chunk 的元数据；
   - 检索时把过滤条件**随查询一起下发**（Chroma `where`，见 `ChromaClient.queryDetail` 四参重载）；
   - 两个调用方都按各自班级过滤：教师端「备课素材」按教师所属班，
     学生端「校本」检索按学生所属班。

**过滤方向是刻意区分的（这一点值得讲）**

| 场景 | 取不到班级时的行为 | 理由 |
|---|---|---|
| 学生端 | **fail-closed：不检索** | "查不到自己班的材料"是可接受的降级；"看到别班的材料"不是 |
| 教师端 | fail-open + WARN 日志 | 班级由角色门保证（无 token 直接 401），取不到只可能是装配错误，不该让备课功能整条不可用 |

**一处措辞要准**：不宜写"无权限的敏感文档**根本不会被 ANN 检索召回**"。
准确说法是**"过滤条件随检索请求一起下发，权限外文档不会出现在返回结果中；
而不是先召回再删除"**——后者有两个实际问题：无权文档仍被召回，且会占掉 topK 名额，
把本班真正相关的内容挤出结果集。

3. **访问校验：`security_level ≤ user_authorization_level`（已实现，且分级两端都是真实量）**

   分级不是"给所有人发同一个数字再比较"，而是：

   | 量 | 取值来源 |
   |---|---|
   | **security_level**（领域等级） | 配置项 `edu.knowledge.access.domain-levels.*`：默认 `1=公开`（通识/心理学）；生命安全与健康教育、青春期性教育配 `2`（需要学生身份）；`3` 预留（教师专用库） |
   | **user_authorization_level**（请求方等级） | 由凭据**推导**、不落库：uid 能对应到一个班级 → `2`；识别不出身份 → `1` |

   闸门装在 `/api/desktop/{domain}/search` —— **只装在"有内容"的接口上**。
   `health` / `libs` 不含任何内容，而知识中心页轮询它们时不带学生标识；
   给它们加闸只会把页面弄坏，换不来隐私收益。

4. **班级级一键开关（已实现，默认开放）**
   表 `edu_class_domain_access(class_id, domain_id, enabled)` —— <b>语义是"默认开放"</b>：
   没有记录即开放，教师停用时才写记录。这样新班级、新专题库都不需要预先铺数据，
   而"停用"这个动作是显式、可审计的。停用只影响本班学生的检索，**不删除任何材料**，恢复开放即回来。

**仍然规划中的（不要按"已实现"讲）**

- 把 `3` 级真正用起来：目前没有"教师专用库"，所以第 3 级只是预留，配置文件里没有领域用它。
- 元数据**按 chunk** 分级（现在等级是领域级的）：只有在同一个库里混放不同密级内容时才需要，
  当前每个库的密级是一致的。

## L4 后置内容校验（**已实现；默认观察模式**）

**机制**：回答生成后，用**独立裁判模型**核查内容是否适合中小学教育场景——
**检索片段与最终输出一起判**（同一次裁判调用，不翻倍成本）：片段是拼进提示词的原材料，
若片段本身不适龄，回答迟早会带出来，等它出现在输出里才拦已经晚了一步。
判据类别限定为：露骨性描述 / 暴力血腥 / 歧视侮辱 / 恐怖惊悚 / 自伤自杀**方法**细节 /
违法实施方法 / 其它不适龄。正常青春期健康教育与生命教育科普**不算**不合适。

> 口径说明：知识库问答路径**片段 + 输出都判**（片段以 `articles` 形式可得）；
> 对话路径只判最终输出——因为对话链路的检索片段是拼进提示词后就不再留存的，
> 要一起判得先把它保留下来（属可做的改进，不要按"已实现"讲）。

**基础设施是复用的，不是新建的**：温度 0、JSON 输出、**熔断器 + 超时降级**、双模开关，
与本项目 `ToolGuardJudgeService`（判"该调工具没调"）完全同一套骨架，
只把判据从"工具调用合规"换成"内容适龄合规"。

**一个必须承认的事实：流式回答撤回不了**（这段请照实讲，评委很容易问到）

| 链路 | 处置 | 说明 |
|---|---|---|
| 非流式（微信）/ 知识库 REST | **替换**成标准提示 | 回答还没返回给用户，能真正拦下 |
| 流式（桌面） | **追加**一条更正提示 + 记 WARN | token 是边生成边推的，等裁判出结果时用户已经看到了 |

即**流式路径的 L4 是"事后更正"，不是"事后拦截"**——这里没有优雅解法，只有如实处理。
固定安全话术（热线引导 / 违规拒绝）**不做校验**：它们是逐字审过的，
再花一次 LLM 既浪费、又有被误判后把热线号码替换掉的风险。

**失败方向与默认模式**：
裁判超时、熔断打开、JSON 解析失败 → 一律"无法判定"，**不阻断**。
理由是内容是"再加一道保险"，不是安全前提（前提是 L1 的关键词闸门），
让它自己挂了就把所有回答替换掉，等于把保险做成了单点故障。
默认 `mode=log` 的理由同理：**每次校验要多一次 LLM 调用**，而判得准不准还没有数据，
所以先观察、把误判率量出来再决定阻断。

**答辩口径**：不要说"我们有一层独立 LLM 校验"（会被追问误报率）。
可以说"内容裁判已接入，复用工具守卫的熔断/降级骨架，当前以观察模式收集误判率；
非流式链路可替换，流式链路因为已输出只能追加更正"。

## ✨ 创新点包装段落（可直接放进创新点章节）

现有 RAG 内容安全方案多在**检索完成或内容生成之后**做过滤，敏感文档仍有被召回的窗口。
本项目把安全管控**前移到链路的每一段之间**，并落到三个**已实现且可验证**的点上：

1. **安全管控真正嵌在路由第一层，命中即终止链路**：安全规则是 L1 的**第一条**规则，
   借漏斗语义短路 L2/L3（含 L3 的 LLM 调用）——**入口即拦截、零大模型调用**；
   自伤风险返回引导话术（含全国心理援助热线）并留一条「班级 + 日期 + 计数」的脱敏信号，
   **不存提问原文、不含学生标识**。且**安全不挂在功能开关上**：路由整层关闭时仍有兜底判定。
2. **学科级命名空间物理隔离 + 校本资源按班过滤**：通识、心理学、生命安全与健康教育、
   青春期性教育、校本资源各自独立向量集合，检索只发生在本学科集合内；
   校本资源在 chunk 元数据里带 `classId`，检索时**过滤条件随查询下发**（而非取回后再删），
   因此别班的材料既不会被召回、也不会占用 topK 名额。学生端取不到班级时 **fail-closed（不检索）**，
   教师端则 fail-open 并告警——两者的取舍在文档里写明了理由，不是随手写的。
3. **教师端权限与聚合的最小化设计**：教师账号与班级**绑定**（班级不进请求参数，改 URL 也拿不到别的班），
   学情看板**全部为聚合查询**（SQL 层不返回学生明细），并在**样本不足时按 k-匿名隐藏数值**。
4. **安全词表必须懂业务，否则会把要保护的对象一起拦掉**（本项目最具体的一处边界判断）：
   青春期性教育知识库的**正常提问本身就在用解剖学词汇**（月经、遗精、避孕、生殖健康），
   法律知识库的正常提问里就有"杀人""盗窃"，健康科普里就有"吸毒""毒品"。
   因此收词只收**明确的实施/索取请求**，不收光杆名词；
   并用**构建期冲突校验**（黑名单与健康教育白名单重叠即启动报错）取代运行期"命中白名单就放行"——
   后者会留下"含健康词即整体放行"的洞。

5. **风险语义层（L2）与内容校验层（L4）复用既有路由与裁判基础设施，不新建体系**：
   L2 与意图分类共用一个 TF-IDF 质心模型（只多一个特殊类），
   L4 与工具守卫共用同一套裁判骨架（熔断/超时/降级）。
   L2 的阈值与 L4 的模式都由**实测**决定，不是拍的（见各自章节）。
6. **人工复核通道与隐私承诺的冲突按"只记类型与计数、不留原句"解决**，
   而不是含糊过去——这是本项目在"安全"与"隐私"之间给出的明确取舍。

## 答辩问答准备（评委最可能问的三句）

**Q1「你这四层都实现了吗？」**
> 两层已实现并可在代码里指给你看（L1 规则闸门、L3 命名空间隔离），
> 另两层有设计且基础设施已具备（L2 复用 TF-IDF、L4 复用裁判骨架），
> 我们如实按"已实现 / 规划中"标注，没有把规划当成果讲。

**Q2「性教育库的色情拦截会不会把正常提问也拦掉？」**
> 会，如果按关键词粗暴拦。所以我们的设计是**只拦露骨与违法模式 + 解剖学与健康词汇白名单**。
> 这个问题本身是我们做这个项目时最具体的边界判断。

**Q3「教师能看到的班级数据是怎么保证不含个人的？」**
> 三层：SQL 只做聚合（不投影 user_id）、响应字段白名单（有测试钉住）、
> 样本不足按 k-匿名隐藏。另外教师账号与班级绑定，**班级不进请求参数**——
> 改 URL、改 body 都拿不到别的班，这一点也有单元测试。
