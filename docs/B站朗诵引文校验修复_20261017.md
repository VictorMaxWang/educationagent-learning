# B站朗诵推荐引文校验修复

本次针对已记录的朗诵推荐失败，冻结同一课堂快照与16个真实视频候选，使用第19版JAR的实际匹配方法复现。匹配模型两次均返回HTTP 200，但结果未通过校验。

## 具体失败字段

| 字段 | 视频 | 失败原因 |
|---|---|---|
| `candidates[11].metadataQuote` | `BV1swoEYCEzp:whole` | 将标题和简介中的分散片段用额外的省略号拼接，原元数据中没有该连续引文。 |
| `candidates[14].metadataQuote` | `BV1FN4y1v7Yx:whole` | 将标题与诗句用额外的省略号拼接，同样不满足连续原文条件。 |

完整重放中，仅将这两处替换为对应视频的真实连续标题，原校验器即通过；其他字段保持不变。这证明拒绝条件有效，问题在于生成结果和修订反馈没有对齐。

## 修复

- 保留原来的类型、长度、候选覆盖、目标归属、适龄及连续子串检查。
- 将引文校验失败归为固定的 `VIDEO_METADATA_QUOTE_INVALID`，审计记录 `contractField` 和 `contractFields`。
- 一次收集同批所有引文错误，并在原有的一次修订机会中同时反馈，避免逐条暴露错误消耗更多模型请求。
- 修订提示明确要求逐字引用连续原文，不得额外插入省略号、拼接或改写。程序不会自动删除省略号、补造引文或改写模型判断来通过校验。
- 字段路径只由固定字段名和0—19的数组下标组成；生产审计不保存原始模型正文或异常原文。

请求次数、总预算、模型、推荐评分和独立最优性验证保持原规则。即使两次响应都保留拼接引文，结果仍应拒绝。
