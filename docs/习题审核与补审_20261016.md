# 课堂习题审核、补审与修题

日期：2026-10-16。本文说明本次改动的机制、**契约变化**和合并检查点，供代码合并与评审使用。

## 1. 解决的问题

生成课堂出现过一道**下发即有害**的题：

- 题干：长方体文具盒长 20cm、宽 8cm、高 3cm，体积是多少？→ `20×8×3 = 480`
- 选项：A 48 / B 240 / C 60 / D 512 —— **没有一个是 480**
- 标答：B（240）—— 错的
- 解析：漏出模型原始推敲「…等等，让我重新计算一下…哦，我刚才心算错了或者选项设置需要调整。让我们修正选项以匹配正确答案 480…」

原链路上**没有任何一层检查答案正确性**：Node 与 Java 都只做结构校验（选项数、去重、标答必须是选项之一——本题恰好通过），内容安全校验只查违禁内容，而 `ClassroomQuizAdapter` 会把错的标答原样存进题库当标准答案，此后 `QuizService` 永远拿它判学生。

## 2. 核心不变量

> **凡是自动计分的题目，答案必须正确。修复不了就不许计分。**

## 3. 机制

### 3.1 生成期两级审核（`course-engine`，落库前）

```
生成 → normalizeQuizQuestions（结构校验，抛异常=整场重试，语义不变）
     → L1 确定性规则（零模型调用，永远开启，命中即丢题）
     → L2 盲解复核（1 次调用，temperature 0）
         ├─ 一致 → review: PASS，正常计分
         └─ 不一致 → 单题就地重出 ≤2 次
                     ├─ 成功 → review: REGENERATED，正常计分
                     └─ 失败 → 移入 content.thinking，review: RISKY_THINK
```

**L1**（`course-engine/src/quiz-review.ts`）：空解析、解析含模型思考过程、选项键非单个大写字母 A–Z、选项正文重复。命中即**丢弃该题**，不抛异常、不中断整课。

**L2**：把本页所有题打包成一次调用，**只传 `{id,type,question,options}`——绝不传标答与解析**。传解析会把错误锚点递回给复核（那题的解析里写着"修正选项以匹配正确答案 480"），把唯一的检测手段变成批量盖章。

### 3.2 降级为不计分思考题

降级题**必须移出 `content.questions`**，放进新数组 `content.thinking[]`。原因：`ClassroomQuizAdapter.submit()` 要求「提交答案数 == 本页题目数」、任何一题留空即 400，前端提交按钮也要求每题都填——留在计分数组里学生会**被迫作答**。

### 3.3 补审（只读）与修题（两段式）

- `POST /api/internal/quiz-review` —— 对**已有课程**跑一次两级审核，报告哪道题不可信。**只读**，不写任何数据。
- `POST /api/internal/quiz-review/repair` —— 出修复方案（`fix-key` / `regenerate` / `none`）。**默认 `apply=false` 只出方案**；`apply=true` 才落库。

**为什么已有课程不能沿用"降级"**：分数分母取自**题库**（`QuizService.submit` 返回的 total 是建卷时写入的题数），而降级改的是**课件文档**里的题目数组，两者会永久错位——学生只做 4 题，界面显示"完成 5 道题"，正确率被系统性低估。项目本身也禁止改动已建卷的练习（`ClassroomEditingSupport` 抛 409）。

因此修题只能「**保持题号与题数不变、就地换题**」：同一事务里更新课件文档与 `quiz_question` 行（判分读题库、学生看课件，两边不能分叉）。**不回改历史成绩**——已提交的 `quiz_answer.is_correct` 保持原样。

## 4. 契约变化（合并时最需要看的部分）

### 4.1 JSONL 协议

`llm.request` 新增**可选** `purpose` 字段，取值 `quiz-review` / `quiz-regenerate`。

- 不带 → 走生成模型（与改动前逐字节一致）
- 带未知值 → `ClassroomNodeEngine` 抛 502 失败关闭
- 用途是 Java 侧路由到 **temperature 0 复核模型**的唯一凭据（生成模型在 `AgentConfig` 里建死 `temperature(0.3)`）

### 4.2 课程文档

| 字段 | 说明 |
|---|---|
| `content.thinking[]` | 新的降级题数组，只有 `id`/`question`/`review`；**空时不写该字段** |
| `content.review.ruleDropped` | L1 丢题数 |
| `question.review` | 每题可选，`{verdict, method, reason}`；verdict ∈ `PASS/REGENERATED/RISKY_THINK/UNVERIFIED` |

剥离规则同时收紧：
- `publicCourse()` 现在也剥 `content.thinking[].review`（**含复核模型自己算出的答案，是泄题**）
- `portable()` / `importPortable()` 剥 `review`（审核结论只对某一次生成成立，随文件流转会冒充"已被核验"）

### 4.3 接口与构造

- `ClassroomEngine` **新增两个方法** `review` / `repair` —— 任何其它实现必须补齐
- `ClassroomTutorModel` 构造函数**新增两个参数** `AiChatProperties`、`ClassroomQuizReviewProperties`；`complete(messages)` 保留 1 参重载，新增 `complete(messages, purpose)`
- `ClassroomNodeEngine.run(...)` 内部拆为 `run(...)` + `runJob(operation, input, outline, token)`
- `ClassroomDocumentValidator.questions(questions)` 保留，新增 2 参重载与 `thinking()`
- `ClassroomCourseService` 新增 `internalDocuments()` / `internalDocument(id)` / `applyQuizRepairs(...)`，以及 `setQuizQuestionMapper` ── 与既有 `setMediaService` 同样的可选注入；应用修复时缺它会**直接失败**而不是只改一半

### 4.4 配置

```properties
# 新增（application.properties）
edu.classroom.quiz-review.enabled=true
edu.classroom.quiz-review.model=            # 留空=沿用统一文本模型
edu.classroom.quiz-review.temperature=0
edu.classroom.quiz-review.max-tokens=1200
edu.classroom.quiz-review.timeout-ms=45000
edu.classroom.quiz-review.max-regenerations-per-question=2
```

**`classroom.engine.timeout-ms` 由 300000 改为 420000，两处都要**：`application-server.properties` 与 `ClassroomNodeEngine` 的 `@Value` 默认值。一个练习页最坏要跑「盲解 + 2 次重出 + 重出后再复核」5 次调用，不调会把「答案错」变成「整课生成失败」。

### 4.5 安全边界

`/api/internal/*` **不得加入 `deploy/linux/Caddyfile` 白名单**。它不匹配现有放行的 `/api/classroom/*`，公网会被 `@privateApi` 兜底成 404——这正是需要的效果：补审与修题要花模型调用、会写数据，不能让匿名访问者触发。

## 8. 诚实边界（不要对外说成"答案 100% 正确"）

**能保证的**：凡计分题都过了两道关（规则 + 独立复算）。

**保证不了的**：

1. **盲解不是独立验证**。复核与出题是**同族模型、temperature 0**，出题错一次复核可能原样再错。它的价值来自上下文差异（批量作答、不看标答与解析），不是独立性。
2. **简答题无法用比对答案复核**，一律 `UNVERIFIED`，会照常计分并由 LLM 语义评阅；文本填空同样不比对（只有纯数值才比）。
3. **复核调用失败**（超时/网络）时题目保留计分并记 `UNVERIFIED`。这是刻意的取舍：不因一次模型抖动就把整页练习清空，用"没题可做"换"答案可能错"。
4. **`PASS` 只表示"第二次也同意"**，不等于正确。因此代码里 `UNVERIFIED` 与 `FAILED` 同级，任何路径都不许把"没算出来"记成 PASS。

**L1 的一个已知取舍**：解析含思考过程时丢弃**整题**偏重（题可能是好的，坏的只有解析）。改成"只重写解析"是 `detectQualityIssues` 里一处标记位的事。

## 9. 未做的事

- **教师工作台审核面板**：未做。风险题只写进 `scene.validation.checks.quizReview` 与逐题 `review`，本机可查；公网课堂没有教师端，因此对公网学生没有可见提示。
- **历史成绩不回改**：已提交的作答仍按当时的标答判。要不要重判是另一个决定。
- **已有课程不会自动被修**：审核只在生成时生效。已有课程要用补审/修题入口单独处理。
