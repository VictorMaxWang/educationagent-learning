# 课堂习题审核、补审与安全修订

更新日期：2026-10-16。本说明对应合入同事修改后的当前实现；旧 DOCX 中的 `fix-key`、无方案编号直接 `apply=true`、以及只保留 `is_correct` 就算保留历史的描述不再适用。

## 1. 本轮修复的具体问题

QQ 中的原题是长方体长 20 cm、宽 8 cm、高 3 cm，体积应为 `20×8×3=480 cm³`。旧选项没有 480，标答却为 B（240），解析还包含修改选项的推敲文字。

新机制将结构、题目质量、盲解结果和解析一致性分开记录。模型仍可能出错：同族模型的两次回答不是数学证明，也不是独立验证。`PASS` 只表示规定的盲解过程与当前标答一致；未取得结论明确记为 `UNVERIFIED`，不能升级为通过。

## 2. 新生成课堂的两级检查

1. 宿主验证五题型及字段、选项、答案结构；生成页为 1—5 题。
2. L1 规则检查空解析、明显自我更正文字、非法选项键和重复选项正文。拒绝计分的题只保留题干，放入 `content.thinking`；即使全页被拒绝，也保留非空思考页，避免给 Java 下发非法空练习。
3. L2 每批最多 5 题，传入 `{id,type,question,options}`，不传参考答案、解析或评分要点。必须回传对应题目的完整、唯一 ID 集；重复、缺失、未知 ID、错误形状不按有效结果处理。
4. 题干超过 800 字或任一选项超过 200 字时整题不送入复核。不会截掉关键条件后仍声称审核通过。
5. 客观题盲解明确不同意时，只重出该题，保持题型，随后重新盲解。重出无可用结果或新答案未被确认时转为不计分思考题。

简答题以及不能作精确数值比较的文本填空不采用字面答案比对，标为 `UNVERIFIED`。原有简答提交仍按参考答案与评分要点作语义评阅，不会改成字符串相等判分。

`UNVERIFIED` 是审核未确定，不等于学生答错。目前新生成链对未明确发现错误的原题保留既有计分行为并记录该状态；不能据此宣称“全部计分题答案已被确定正确”。学生提交阶段如果语义判分未知，课堂仍按既有事务边界回滚整组，不写入伪造错题。

数值填空审核使用十进制字符串规范化，避免 JavaScript Number 将两个不同大整数或高精度小数舍入成相同值。

## 3. 既有课程：先出固定方案，再应用

### 只读补审

`POST /api/internal/quiz-review?courseId=<课程ID>`

省略 courseId 时读取现有课程列表。旧页允许 1—10 题，按最多 5 题分批，保留已有题目 ID。报告将规则问题、明确分歧和 `unjudged` 分开；失败不写成“没有问题”。补审不修改课程、题库或成绩。

### 准备方案

`POST /api/internal/quiz-review/repair?courseId=<课程ID>`

默认只读生成修复建议。每门有可应用变更的课程返回一个 `planId` 和 `expiresAt`。方案仅在当前服务进程保存 15 分钟，最多 32 份；服务重启后须重新准备和审阅。

现在只支持：

- `regenerate`：完整同题型重出，重新盲解同意，并另行检查新题干、选项、标答与解析一致。
- `none`：未确认、类型不支持自动修订或本次预算用尽，交人工或另行准备。

已关闭 `fix-key`。只把 B 改成 A 会保留“20×8×3=240，所以选 B”这样的错误解析，不能算修好了。解析一致性检查与盲解是不同调用，前者会看到新标答，不能把它包装成盲解证据。

### 应用已审阅方案

`POST /api/internal/quiz-review/repair?courseId=<课程ID>&apply=true&planId=<已审阅编号>`

应用不会重新调用模型。重复应用同一有效编号返回原回执；失败的编号也不会自动再次写入。未提供 planId、方案过期、课程不匹配或内容变化会明确拒绝。

后端重新核对课程内容指纹、场景、题号、题目 ID 和原题快照；重新执行宿主五题型校验，规范化选项键与答案，并验证题库行存在、实际更新行数恰为 1。任何题无法确认时整组事务回滚。

**已有任何作答记录的原题禁止原位修订。** 即使不改 `quiz_answer.is_correct`，覆盖原题干后，错题本仍会把旧答案拼到新题目，已经破坏历史事实。当前策略保留原题、标答、解析、成绩与错题，另建课程修订版。

## 4. 已有作答题：副本与单向修订指针

先通过正常导出/导入建立修订课程，确认新课题干、选项、答案与解析正确。然后使用内部登记接口：

```json
POST /api/internal/quiz-revisions
{
  "oldCourseId": "原课程ID",
  "oldSceneId": "原练习页ID",
  "newCourseId": "修订课程ID",
  "newSceneId": "修订练习页ID",
  "reason": "题目答案和解析已修订，历史作答保留",
  "requestId": "本次登记的唯一编号"
}
```

登记校验两端课程、页面、试卷及题库归属，拒绝覆盖、自指、循环和超长链；同请求同载荷可重放。仅向现有学习状态表新增不可覆盖指针和请求索引，不写原课程 JSON、原题库行或历史答卷。

公开查询：`GET /api/classroom/courses/{id}/quiz-revisions`，返回当前课页面到最终修订页的白名单映射。旧课堂显示新版入口，禁用旧题提交；错题列表附加可选 `revision` 字段显示历史题标记与新版入口。原错误解析不会被展示为新版教材依据。

旧卷的即时判题、整卷提交及错题重做统一检查指针并返回 409；不会用已撤下的旧标答继续判断学生。

## 5. 并发、事务与模型调用预算

当前部署为单 JVM 实例。`QuizMutationGuard` 使用试卷条带锁，修题锁顺序为课程锁 → 试卷锁 → 数据库事务。常规交卷与重做在首次 SQL 前取得同一试卷锁；存在外层 Spring 事务时，锁由 `afterCompletion` 回调释放，不能在服务方法返回、事务尚未提交时提前释放。

修订指针注册为登记写锁 → 试卷锁 → 事务；读取与判分检查不取得登记写锁，也不在试卷锁内调用 CourseService 的课程锁，避免锁顺序反转。多实例部署需要独立设计跨实例互斥，当前实现不作该保证。

模型边界：

- 网络错误、响应结果未知或盲解格式不完整，不自动再次发送相同付费请求。
- 重生成只在已收到完整但结构或已知语义不合格响应时使用剩余预算；网络异常立即终止本次重生成。
- 生成页 Node 最多 5 题，单题重生成默认 2 次（配置硬上限 3）。包含出题、初次盲解、重出、重出后批量盲解及讲授动作，默认最坏 **14 次**、硬上限 **19 次**模型请求。
- 补审最多两批，即 **2 次**盲解请求；跳过或首批结果未知会减少实际调用。
- 一次旧页修题最多准备 5 个完整修复：最多 2 次初审，加每题 1 次重出、1 次盲解和1次解析检查，最坏 **17 次**。其余题明确标为另行处理。
- Node 桥仍限制每作业最多 20 次请求、总时限 420 秒。外层既有课堂教学检查、安全服务和媒体服务的调用不包含在上述 Node 请求数中，分别按各自预算记录，不能把 420 秒宣称为整门课程总时长。
- 服务端异常日志仅记录用途与类型，不写原始供应商异常正文或凭据。

## 6. 必须验证的回归

- 480 原例：选项缺正确答案与含推敲解析都能被标记；新建议必须同题型、答案及解析一致。
- 五题型、同义简答及数值零保持可用；短答的 `NONE` 不误当答案分歧。
- 长选项、重复/缺失 ID、非法 JSON、未知结果与网络错误不形成虚假 `PASS`，也不自动重发。
- 全部 L1 拒绝仍产出合法思考页，思考题不建卷、不提交、不泄露标答。
- 旧 6—10 题页能够分批补审，原题号和 ID 不变。
- planId 应用不再生成；重复应用幂等，过期、错课、内容变化与已有作答全部拒绝。
- 真实 SQL 验证课程与题库整组回滚；并发测试验证首次作答事务提交前，修题不能越过锁。
- 修订指针不改变任何原记录；旧卷所有判分入口 409，公开映射和错题 revision 只包含允许字段。
- 导入导出与公开场景继续剥离逐题审核内部证据，不继承来源版本的通过状态。

内部补审、准备、应用和修订登记接口均不得加入公网反向代理白名单。本文描述代码机制；实际上线、真实模型与生产修订记录以本轮最终验收回执为准，不能用单测或模拟模型替代。
